Known differences from R limma
==============================

pylimma is validated against R limma using pre-computed CSV fixtures
generated by ``tests/fixtures/generate_all_fixtures.R``. The target
tolerance is ``rtol=1e-6, atol=1e-12`` for deterministic statistics,
and a log10-scale comparison for p-values.

The sections below document every numerical gap that remains after
porting.

Accepted differences
--------------------

Eight differences remain after porting. None is a porting bug: seven
come from numerical-algorithm choices and one (lowess) from how R
itself is built on different platforms. Each is quantified and
reproducible, and the parity tests stay within the tolerances given.

normexp saddle-point fit drifts up to ~2e-4 from R
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``normexp_fit(method="saddle")`` parameters match R within
``rtol ~2e-4``; the objective function value agrees to
``rtol ~6e-9``. ``method="mle"`` matches R to ``rel ~2e-13``;
``method="rma"``, ``method="rma75"``, and ``normexp_signal`` all match
R at floating-point precision.

**Root cause.** scipy's Nelder-Mead and R's ``nmmin`` implement the same
algorithm but differ in the initial simplex, the termination rule and
the details of their reflection and shrink steps. R stops when
``VH - VL < intol * (|f(x0)| + intol)`` with ``intol = sqrt(eps) =
1.49e-8`` (``~4e-4`` at the saddle objective scale, ``f ~ 25000``);
pylimma's scipy call uses absolute ``fatol = xatol = 1.49e-8`` and at
most 500 iterations, so it runs further and lands at a slightly better
f at a different point on the flat saddle-likelihood plateau. Giving
scipy R's initial simplex and stopping rule (as ``genas`` does) does not
bring it closer: the largest parameter difference grows from ``2e-4`` to
``5e-4`` on the fixtures, so the fit keeps its own settings.

**Tolerance.** Parity tests for ``method="saddle"`` use
``rtol=1e-3``. All other normexp methods are at ``rtol=1e-10`` or
better.

genas covariance and correlations agree with R to ~6e-4
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``genas`` fits its two likelihoods with scipy's Nelder-Mead, given R's
``optim()`` settings: R's initial simplex (every coordinate stepped by
``0.1 * max|x0|``), R's stopping rule (the simplex's function values
within ``sqrt(eps) * (|f(x0)| + sqrt(eps))``) and R's 500 evaluations.
The reflection and shrink steps are scipy's, so the search ends at a
slightly different point of the flat likelihood: the deviance and p-value
agree with R to ``rtol ~2e-6``, the fitted covariance matrix and the
biological correlation to ``rtol ~6e-4``.

**Tolerance.** Parity tests use ``rtol=1e-6`` for the deviance, the
log-scale comparison for the p-value and ``rtol=1e-3`` for the
covariance and correlations.

normexp_signal is more accurate than R when sigma^2 / alpha is large
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

When the normal part is narrow next to the exponential mean, the
expected signal ``mu.sf + sigma * h(z)`` (``h`` the normal hazard, ``z``
in the thousands) is a small difference of large terms. R computes ``h``
as ``exp(dnorm(log=TRUE) - pnorm(log.p=TRUE))``, whose exponent carries
rounding error of order ``eps * z^2``: for ``par = (100, log(10),
log(0.002))`` R's signals jitter between 0.0019998 and 0.0020545 where
the exact values (asymptotic Mills-ratio series) rise smoothly from
0.0019984 to 0.0020161, an error of up to 2.8%. For ``z > 0`` pylimma
computes ``sigma * (h(z) - z)`` without the cancellation: ``h(z) - z``
from the Mills-ratio continued fraction ``1 / (z + 2 / (z + 3 / ...))``
for ``z > 3`` and ``h = sqrt(2/pi) / erfcx(z / sqrt(2))`` for ``0 < z <=
3``. It is exact to rounding, so it differs from R by R's error in this
regime and matches R to 1e-12 elsewhere.

**Tolerance.** Parity tests compare with the exact values at
``rtol=1e-12`` and with R at ``rtol=1e-4`` (``alpha = 0.01``) and
``rtol=1e-12`` (``alpha = 20``).

Monte-Carlo rotation tests (``roast``, ``mroast``, ``romer``, ``gene_set_test``)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Rotation-based gene-set tests draw rotations from NumPy's PCG64 RNG.
R uses the Mersenne Twister inside its own ``sample.int`` / ``rnorm``
C routines. The two streams cannot be aligned byte-for-byte from the
same seed. Deterministic summaries match R to ``rtol=1e-15``:

- ``ngenes_in_set``
- observed test statistics
- active proportions ("PropDown" / "PropUp")
- the rotated-effects matrix when the rotation seed is matched
  post-rotation (e.g. via ``compare_pvalues(max_log10_diff=0.5)``)

Monte-Carlo p-values from ``roast`` / ``mroast`` / ``romer`` /
``gene_set_test`` agree with R within sampling error.

**Tolerance.** Empirically ~0.3 log10 (factor of 2) between R and
pylimma at ``nrot=999`` on the gene-set-testing fixture data, well
inside the documented ``max_log10_diff=0.5`` threshold.

mrlm stdev_unscaled drifts up to ~15% on machine-epsilon residuals
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

When a gene is perfectly fit by the design (initial OLS residuals at
machine epsilon), ``mrlm`` and R ``MASS::rlm`` produce different
``stdev_unscaled`` values - up to 15% relative difference. The trigger
is exclusive to synthetic perfectly-fit rows; real proteomics or
RNA-seq residuals are 6+ orders of magnitude above machine epsilon
and unaffected.

**Root cause.** R's ``lm.wfit`` uses LINPACK ``DQRDC2`` which produces
mixed-sign machine-epsilon residuals on a degenerate row. scipy's
``np.linalg.lstsq`` uses LAPACK SVD which produces uniform-sign
residuals. The iter-1 MAD scale picks up R's mixed-sign noise pattern
and Huber-downweights three samples as "outliers"; pylimma's MAD
gives unit weights everywhere and returns the unweighted OLS stdev.
Both implementations are computing deterministic numerical noise -
just different noise patterns - because the residuals carry no
information about the underlying linear model.

**Tolerance.** A regression sentinel test
(``tests/rigorous/test_mrlm.py::test_b9c_zero_residual_scale``) is
left as ``xfail`` rather than loosened, so any future numerical
change that aligns the two patterns is detected automatically.

**Note.** Downstream impact is zero: when a row hits this regime
``sigma`` is also at machine epsilon, t-statistics are inf/NaN,
and the empirical-Bayes posterior is dominated by the prior
regardless of which "garbage" stdev was returned.

lowess fits through three or fewer points follow rounding noise
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

pylimma's lowess (used by ``voom``, ``vooma``, ``loess_fit`` and so the
trends of ``e_bayes`` and ``squeeze_var``, and cyclic loess) is a port of
R's ``stats`` ``lowess.c``. It gives the same result, bit for bit, as
that C code compiled without fused multiply-adds, as R is on x86-64
Linux (8,800 test cases).

**Root cause.** R on macOS arm64 is compiled with multiply-adds fused
(clang's default), which changes the last bit of some sums. Where every
local fit uses three points or fewer (fewer than about 20 points with
a small span), each fit passes exactly through its points, and the
robustness weights are then set by that last-bit noise, so R itself
gives different curves on the two platforms (up to 18.8 apart on an
8,800-case grid). With four or more points per
fit, pylimma matches R on macOS arm64 to 4e-11 relative on the same
grid.

**Tolerance.** The parity fixtures use at least four points per fit
and are compared at ``rtol=1e-6`` or tighter.

fit_f_dist_robustly: df2 root differs in the eighth digit
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``fit_f_dist_robustly`` (and so ``squeeze_var`` / ``e_bayes`` with
``robust=True``) finds ``df2`` with scipy's ``brentq``; R uses
``uniroot``, whose C ``zeroin`` is another implementation of Brent's
method. Both stop at ``tol = 1e-8`` on the ``df2 / (1 + df2)`` scale, at
slightly different points, so ``df2`` differs by up to ``1.3e-8``
relative, more for large ``df2`` (where the root is near 1).

**Tolerance.** Inside ``rtol=1e-6``; the robust parity tests pass at
``1e-8`` except the extreme-outlier case, which is compared at
``1e-6``.

fry with observation weights depends on the QR's residual basis
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``fry`` (R's ``.lmEffects``) rotates each gene's data by the Q of a QR
decomposition of the design: the first effect is the contrast and the
others span the residual space. With observation weights (e.g. from
``voom``) every gene has its own QR. The method does not fix which
orthonormal basis of the residual space is used; the numbers do depend
on it, because ``fry`` averages each residual effect over the genes of a
set and, for ``standardize="posterior.sd"`` (the default), ``"p2"`` or
``"residual.sd"``, removes each gene's largest squared residual effect.

**Root cause.** For some designs the pivot element of the last
Householder step is zero in exact arithmetic: for example a
``~0 + group`` design with a contrast between two groups, reformed so
that the contrast is its last column. In floating point it is rounding
noise (about ``1e-17``), and its sign decides the direction of the last
reflection and so the residual basis. R (LINPACK's ``dqrdc2``) and pylimma
(LAPACK) reach that step with different rounding, so for some genes the
signs differ. Under the model the residual effects are independent with
the gene's variance in any orthonormal basis, so neither basis is more
correct than the other; R's own result could change with its BLAS or
platform. pylimma does not try to reproduce R's rounding.

**Size.** On GSE60450 (voom weights, 12 samples, 6 residual df), contrast
``luminal.pregnant - luminal.lactate``, p-values for 30 random sets
differed from R by up to 2.1-fold given R's voom weights, and by up to
3.7-fold (5.3e-4 vs R's 1.4e-4) given pylimma's own voom weights, which
differ from R's by only ``3e-13`` relative; the other two contrasts
tested agreed with R to ``1e-14``. ``standardize="none"`` is affected too,
because ``fry`` averages each residual effect over the set's genes (0.934
vs R's 0.930 for one of four sets of the synthetic fixture). Unweighted
fits matched R in every case checked.

**Tolerance.** The contrast effect and each gene's residual sum of
squares do not depend on the basis and are compared with R at
``rtol=1e-6`` (``TestFryBranchParity::test_residual_basis_invariants_match_r``).

Deliberate divergences: intended rather than literal R behaviour
----------------------------------------------------------------

Where R limma contains a clear bug, pylimma follows the behaviour the
limma code evidently intends rather than reproducing the bug. Each
case below is tested against a reference computed in R with the
single-line correction applied, and the literal R behaviour is
recorded in the fixtures alongside it.

decide_tests: hierarchical method with a supplied genewise_p_value
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

For a matrix of p-values, ``decideTests.default(method="hierarchical",
genewise.p.value=...)`` in limma 3.66.0 fails with
``object 'ngenes' not found`` for every ``adjust.method`` except
``"none"``. ``ngenes`` is defined only inside the branch that
computes Simes genewise p-values when none are supplied, but the
p-value cut-off multiplier uses it in both cases.

pylimma uses ``ngenes = nrow(p)`` in both cases. The reference
fixtures (``R_dt_p_hierarchical_genewise_*_intended.csv``) come from
R's ``decideTests.default`` with ``ngenes <- nrow(p)`` inserted before
its ``switch()``; the fixture script checks that the patched function
reproduces R exactly wherever R itself succeeds.

normalize_cyclic_loess: missing values with ``"pairs"`` and ``"affy"``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

In ``normalizeCyclicLoess(method="pairs")`` and ``"affy"``, a pair fit
has no fitted value where either array is missing, and adding that NA to
both arrays spreads it, so a row with one missing value ends up NA in
every array. ``"fast"`` keeps the other arrays' values, because it
averages the rows with ``rowMeans(na.rm=TRUE)``; the pair methods do not
handle missing values at all.

pylimma gives such a row no adjustment from that fit, so in all three
methods only the missing cells stay NaN, also when a whole array is
missing (R then returns every array it is paired with all NA); through
the later fits the other rows differ slightly from R's. The reference fixtures
(``R_cyl_na_pairs.csv``, ``R_cyl_na_affy.csv``) come from R's
``loessFit`` with the missing fitted values set to 0 (``.cyl_keep`` in
the fixture script), which reproduces ``normalizeCyclicLoess`` exactly
on data without missing values; the fixture script also checks that R
turns those rows NA. A row holding an infinite value is returned all
NaN, as in R, which gives no warning; pylimma warns.

gls_series: ``spacing=None`` with an estimated correlation
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``gls.series`` sets a NULL ``spacing`` to 1 (``if(is.null(spacing))
spacing <- 1``), but only after it has called ``duplicateCorrelation``
for a missing ``correlation``, which fails on the NULL in ``unwrapdups``
("dims [product ...] do not match the length of object"). pylimma reads
``spacing=None`` as 1 before both steps. ``generate_all_fixtures.R``
records the R behaviour.

Conditions with misplaced parentheses in ``plotMD`` and ``plotRLDF``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``plotMD.MArrayLM`` tests ``if(ncol(status == ncol(object)))``, which is
always true, so a status with several columns always gives its column
``column``, whatever its number of columns (R stops only when that column
does not exist). ``plotRLDF`` tests ``any(show.dimensions) > ndim`` and
``any(show.dimensions) > n``, which compare ``TRUE`` (1) with the number,
so ``ndim`` is never raised to the largest shown dimension and a
dimension beyond the samples is not caught. pylimma follows the evident
intent: ``plot_md`` raises "status has multiple columns" unless the status
has one column per coefficient, and ``plot_rldf`` raises ``ndim`` to the
largest shown dimension and rejects one beyond the samples.

genas: logFC / predFC subsets re-centre the coefficients
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

In ``genas(subset="logFC")`` and ``genas(subset="predFC")``, limma
assigns the re-centred coefficients to ``fit$coeff``. R's ``$<-`` does
not partial-match, so this creates a new list element and the
re-centring never reaches the likelihood, which reads
``fit$coefficients``. pylimma applies the re-centring as the code
intends.

fit_f_dist_unequal_df1: two informative values with zero prior weights
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

With exactly two informative variances, ``fitFDistUnequalDF1`` sets
``prior.weights <- NULL`` to fit them without weights. But
``PriorWeights <- !is.null(prior.weights)`` has already been computed, so
if any prior weight existed - including the zero weights the function
itself creates for missing ``x`` or ``df1 < 0.01`` - limma 3.66.0
multiplies by ``NULL`` and returns ``scale = NaN``. pylimma clears the flag
together with the weights. The reference is R's function with
``PriorWeights <- !is.null(prior.weights)`` repeated after the reset;
``tests/rigorous/test_fit_f_dist_unequal_df1.py`` checks that unpatched R
returns NaN and that pylimma matches the patched function.

voom_with_quality_weights: sample weights when genes equal samples
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``voomWithQualityWeights`` passes the estimated sample weights to its
second ``voom`` as a plain vector. ``asMatrixWeights`` reads a vector whose
length equals the number of genes as gene (probe) weights before it
considers array weights, so when there are exactly as many genes as
samples R uses the sample weights as gene weights. pylimma passes them as
a 1 x N row matrix, which is always read as array weights. The reference
fixtures (``R_vqw_square_*_intended.csv``) come from R's steps with that
one change; the fixture script checks that they reproduce
``voomWithQualityWeights`` whenever the number of genes differs from the
number of samples.

Names of unnamed gene sets
~~~~~~~~~~~~~~~~~~~~~~~~~~

For an unnamed list of gene sets, R's ``mroast`` and ``fry`` name the sets
``set1``, ``set2``, ... (zero-padded from ten sets: ``set01``), while R's
``camera``, ``cameraPR`` and ``romer`` leave them unnamed, so their result
rows are labelled ``"1"``, ``"2"``, .... pylimma uses the ``set1`` naming in
all of them, so results of different tests can be joined on the set name.
A single set passed on its own is ``set1`` (``romer``: ``set``, as R).

gene_set_test simulation: exact ties
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

With ``ranks_only=False``, ``geneSetTest`` counts random sets whose mean is
at least the observed mean, so ties are decided by rounding. R's ``mean()``
sums in long double: on Linux (x86-64, extended precision) a permutation of
the same values ties exactly, and a set of all genes gives p = 1, but on
platforms where long double is ordinary double (e.g. macOS on Apple
silicon) the same call gives values such as 0.999 or 0.5. pylimma compares
exactly rounded means (``math.fsum``), so ties are always exact and the
result does not depend on the platform; it agrees with R on Linux.

``top_go`` / ``top_kegg``: order of names tied on p-value and size
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Rows tied on both p-value and number of genes are ordered by term or
pathway name. R's ``order()`` compares text with the collation of the
user's locale (in ``en_GB``: apoptosis, Apoptosis, b, Wnt signaling);
pylimma compares by code point (Apoptosis, Wnt signaling, apoptosis, b),
as R does in the ``C`` locale, so the order is the same on every machine.

Formula designs: column order and names
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

pylimma builds designs from formula strings with patsy rather than R's
``model.matrix``. The columns span the same space and give the same fitted
values, but their names and order can differ:

- names follow patsy: ``g[T.b]`` for R's ``gb``, ``Intercept`` for
  ``(Intercept)``;
- patsy puts the terms of a categorical factor before those of a numeric
  one: ``~ age * g`` gives ``Intercept, g[T.b], g[T.c], age, age:g[T.b],
  age:g[T.c]``, where R gives ``(Intercept), age, gb, gc, age:gb,
  age:gc``, and ``~ age + I(age > 3)`` swaps its two terms;
- an interaction without its main effects (``~ g:h``) is coded with a
  full-rank set of columns (6 for a 3 x 2 layout), where R gives 7
  rank-deficient columns;
- a formula sees the columns of the data, patsy's built-ins (``C``, ``I``,
  ``Q``, ``Poly``, ...), ``np`` and ``pd``, where R's formula also sees
  the variables of the environment it was written in.

Main-effect formulas such as ``~ group``, ``~ 0 + group`` and ``~ a + b``
give R's columns in R's order. For other formulas, a coefficient position
taken from R code (``coef = 3``) can refer to a different column;
``model_matrix_with_names`` and the fit's ``coef_names`` give the names.

``make_contrasts`` without contrasts
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

With no contrasts, ``make_contrasts`` raises "No contrasts specified". R's
``makeContrasts`` returns a matrix with one row per level and no columns for
``contrasts = character(0)``, and fails with "length of 'dimnames' [2] not
equal to array extent" when ``...`` is empty. pylimma reports the missing
contrasts where they arise instead of returning a matrix with no columns.
``generate_all_fixtures.R`` records the R behaviour.

vooma: missing values in y
~~~~~~~~~~~~~~~~~~~~~~~~~~

limma's NEWS for 3.64.0 says "vooma() now allows missing values in both
``y`` and ``predictor``, provided there are no entirely missing rows",
and ``vooma.R`` checks for entirely missing rows and for missing
predictors, but its ``lm.fit`` calls still fail on any missing value
("NA/NaN/Inf in 'y'"). pylimma's ``vooma`` fits each gene on its
observed values with ``lm_fit``, as ``voomaLmFit`` does in R: the fitted
values are ``coefficients %*% t(design)`` and the variance is
``sigma^2``, which on complete data equal ``vooma``'s ``lm.fit`` values.
Two cases follow ``voomaLmFit`` as it would behave without R's
accidents:

* A gene with a coefficient that cannot be estimated from its observed
  values (for example a group entirely missing) gets NaN weights for
  every sample, as in ``voomaLmFit``.
* A gene with no residual degrees of freedom has no variance estimate
  and is left out of the mean-variance trend. R's ``lowess`` computes
  with its NA, which in a 200-gene test turned 89 of the 200 trend points
  into NA and moved the other genes' weights by up to 18.5%.
  ``vooma_lm_fit`` does the same in both of its trend fits; its reference
  (``R_lowess_voomalmfit_*.csv``) is R's ``voomaLmFit`` with both
  ``lowess`` calls applied to the genes with a finite ``sigma``, which the
  fixture script checks equals ``voomaLmFit`` when every gene has
  residual degrees of freedom.

The reference fixtures (``R_vooma_na_*.csv``) come from ``vooma.R`` with
``lm.fit`` replaced by ``lmFit`` and such genes left out of the trend;
the fixture script checks that this reference reproduces R's ``vooma``
on complete data (with and without block and predictor) and R's
``voomaLmFit`` weights with missing values. Infinite values still raise
an error.

Clear errors where R fails obscurely or behaves accidentally
------------------------------------------------------------

For some invalid or degenerate inputs, R limma either stops with a
message from deep inside the computation or returns a result produced by
accident (for example by recycling or by ``NULL`` propagation). pylimma
raises a ``ValueError`` that names the problem instead. Valid inputs are
unaffected.

``decide_tests`` with ``method="hierarchical"`` or ``"nestedF"`` on a fit without F-statistics
    ``e_bayes`` computes F only when the fit has a full-rank design. R's
    ``decideTests`` then passes ``F.p.value = NULL`` to ``p.adjust()``,
    selects nothing and returns all zeros; pylimma raises an error saying
    that F-statistics are needed. ``generate_all_fixtures.R`` records the
    R behaviour.

``remove_batch_effect`` with a missing ``batch`` / ``batch2`` label
    A missing label (``None``, pandas NA, a categorical NaN, or NaN among
    string labels) raises "batch contains missing labels". R's ``as.factor`` leaves NA out of the levels,
    and ``removeBatchEffect`` then stops with "not enough degrees of freedom
    to define contrasts" or "number of rows of matrices must match". As in
    R, a numeric NaN is not missing but a level of its own.

``remove_batch_effect`` with ``batch`` / ``batch2`` / ``covariates`` of the wrong length
    Raises "<argument> has <k> rows/values, but there are <n> samples"
    (R: "number of rows of matrices must match (see arg 2)" from ``cbind``).

Character gene sets without gene IDs (``roast``, ``mroast``, ``fry``, ``camera``, ``camera_pr``, ``romer``)
    A set given as gene IDs needs IDs to match against: the row names of
    ``y`` (``adata.var_names``, a DataFrame index) or ``geneid=``. Without
    them pylimma raises an error; R matches against ``NULL`` row names and
    silently tests an empty set. Likewise ``gene_set_test``,
    ``wilcox_gst`` and ``rank_sum_test_with_correlation`` select a character
    set by the names of ``statistics`` (a pandas Series) and raise an error
    for a name that is not among them. R's ``statistics[name]`` is NA, so
    the p-value is silently NA, except in ``geneSetTest(ranks.only=FALSE)``,
    which drops the NA and tests the remaining genes.

Gene-set positions outside the statistics (``gene_set_test``, ``wilcox_gst``, ``rank_sum_test_with_correlation``, ``barcode_plot``)
    A position must lie in 0..n-1 for ``n`` statistics, else pylimma raises
    "gene set position ... is outside the 0-based positions 0..n-1 of
    statistics". In R a position past the end subscripts NA, so the
    p-values are NA (``barcodeplot`` drops the gene), and a negative
    position drops that gene from the set; read as 0-based, a negative
    position would instead count from the end. Likewise a logical set must
    have one value per statistic: R recycles a shorter one and gives NA
    for a longer one. ``generate_all_fixtures.R`` records the R behaviour.

Logical subscripts of the wrong length (``EList`` / ``MArrayLM`` subsetting)
    A logical row or column subscript must be a single value (recycled, as
    R's ``TRUE``) or have one value per row or column; pylimma raises "a
    logical subscript has ... values for ... rows". R recycles a shorter
    one silently.

``au_roc`` with a ``truth`` that is not logical
    ``truth`` is read as R's ``as.logical``: numbers, or the strings R
    recognises ("TRUE", "true", "True", "T" and the FALSE forms). Any other
    string raises "truth must be logical, numeric or 'TRUE' / 'FALSE'
    strings"; R turns it into NA and stops with "missing value where
    TRUE/FALSE needed". A character ``stat`` is ranked by code point, where
    R's ``order()`` follows the locale. ``generate_all_fixtures.R``
    records the R behaviour.

``contrasts_fit`` with a ``cov_coefficients`` of the wrong size
    Raises "cov_coefficients has shape (r, c), but the fit has p
    coefficients". R
    fails in ``chol(cov) %*% contrasts`` with "non-conformable arguments";
    pylimma returned a result without complaint. ``generate_all_fixtures.R``
    records the R behaviour.

``top_table`` with an empty or logical ``coef``
    Raises "coef must give at least one coefficient". R's
    ``fit$coefficients[, integer(0)]`` is empty, and ``topTable`` returns
    an empty data frame. A logical ``coef`` raises "coef must be
    coefficient positions or names, not logical"; R's ``coef = TRUE``
    fails while building the table ("duplicate 'row.names' are not
    allowed"). ``generate_all_fixtures.R`` records the R
    behaviour.

A missing ``block`` label (``lm_fit``, ``gls_series``, ``voom``, ``duplicate_correlation``)
    Raises "block contains missing values" for a NaN, None or pandas NA
    label. R has no check: for NA, ``lmFit`` and ``voom`` fail in ``chol()``
    ("the leading minor of order 2 is not positive") and
    ``duplicateCorrelation`` in ``qr.qty()``. For a numeric NaN, which numpy
    cannot tell from NA, ``lmFit`` and ``voom`` fail the same way, while
    ``duplicateCorrelation`` makes NaN a block of its own (factor()) and
    runs; pylimma raises in all three (John's choice; a NaN label in Python
    usually means a missing one). ``remove_batch_effect`` keeps R's rule
    that a numeric NaN batch is a level (see its entry).
    ``generate_all_fixtures.R`` records the R behaviour.

``lm_fit`` with no samples, ``is_fullrank`` with missing or infinite values
    Raise "expression matrix has zero columns" and "infinite or missing
    values in 'x'". R fails in ``lm.fit`` ("0 (non-NA) cases") and in
    ``eigen()``; pylimma returned an all-NaN fit and ``False``.
    ``generate_all_fixtures.R`` records the R behaviour.

``decide_tests`` / ``classify_tests_f`` with unusable arguments
    ``decide_tests(p_value=NaN)`` raises "p_value must be a number"; R's
    ``p < NA`` gives an all-NA result. With several coefficients,
    ``classify_tests_f`` raises for a ``p_value`` outside 0..1, a ``df``
    that leaves no F threshold (0 or NaN) and a ``cor_matrix`` with missing
    values or no positive eigenvalue; R fails in ``qf`` / ``eigen`` /
    ``if()`` ("missing value where TRUE/FALSE needed"). With one
    coefficient, as in R, any ``p_value`` is compared with the p-values. ``generate_all_fixtures.R`` records the R behaviour.

``genas`` with unusable coefficients
    A ``coef`` outside the coefficient positions, a fraction or a repeated
    coefficient raises a clear error, as does a pair of coefficients whose
    covariance matrix is singular (such as two identical contrasts). R's
    ``fit[, coef]`` truncates a fraction and fails for an out-of-range
    position, and a repeated coefficient or identical contrasts fail in
    ``chol()`` while the likelihood is searched; pylimma returned results
    (Python's negative positions counted from the end).
    ``generate_all_fixtures.R`` records the R behaviour.

``fitmixture`` with one array or one ``mixprop``
    Raises "mixprop must take at least two different values". R's
    ``lm.fit(cbind(mixprop, 1 - mixprop), ...)`` gives NA coefficients,
    which fail a later assignment ("NAs are not allowed in subscripted
    assignments"); pylimma returned a minimum-norm fit. ``niter`` must be a
    whole number, as ``nrot`` (R's ``1:niter`` truncates).
    ``generate_all_fixtures.R`` records the R behaviour.

``background_correct`` with degenerate input
    A ``background`` not of the shape of the expression matrix raises
    R's "non-conformable arrays" (numpy would broadcast a column, row or
    scalar). A column with no value above background under
    ``method="minimum"`` raises; R's ``min()`` of nothing gives ``Inf``
    (with a warning), so every value below background became ``Inf``. An
    ``offset`` that is NaN or more than one value raises; R's ``if(offset)``
    fails with "argument is not interpretable as logical" for NaN and "the
    condition has length > 1" for a vector. ``generate_all_fixtures.R``
    records the R behaviour.

``vooma_by_group`` with a missing group label, or only singleton groups
    A missing group label raises; R gives that sample no group, so its
    "weights" are its expression values. A level with no samples (an
    unused category) raises a clear error; R fails in ``vooma`` on the
    empty subset ("y contains entirely NA rows"). When every group has one sample
    (possible with a design other than the default ``~0 + group``), the
    span is that of the fit to all samples; R fails with "object 'voomi'
    not found".

``voom`` with a ``lib_size`` of the wrong length
    A ``lib_size`` that is neither one value per sample nor a single value
    raises. R's ``matrix(lib.size, n, ncol, byrow = TRUE)`` recycles it
    across the samples. ``generate_all_fixtures.R`` records the R
    behaviour.

``make_unique`` with a missing value and a repeated value
    Missing values stay missing and the repeated values are numbered. R's
    ``makeUnique`` fails with "NAs are not allowed in subscripted
    assignments" (it keeps NA when no other value repeats).
    ``generate_all_fixtures.R`` records the R behaviour.

``logsumexp`` with ``x`` and ``y`` of different lengths
    Raises unless one of them is a single value. R's ``pmin`` / ``pmax``
    recycle the shorter one, so ``logsumexp(c(1, 2), c(3, 4, 5, 6))`` pairs
    1 with 5 and 2 with 6. ``generate_all_fixtures.R`` records the R
    behaviour.

``select_model`` with a 1-D ``y``
    A 1-D ``y`` is one gene, as for ``lm_fit``, and the criterion counts its
    values as the arrays: the result equals R's
    ``selectModel(matrix(y, 1), ...)``. R's ``selectModel(y, ...)`` fits the
    vector as one gene too but takes the number of arrays as
    ``ncol(as.matrix(y))``, which is 1. ``generate_all_fixtures.R`` records
    the R behaviour.

``prop_true_null`` with missing p-values
    Raises "Missing values in p not allowed" (R's ``convest`` error) for
    ``method="lfdr"`` and ``"mean"``. R's ``sort()`` drops the NA and the
    arithmetic then recycles the shorter vector, with a warning, into an
    arbitrary number. ``"hist"`` leaves them out, as R. ``nbins`` must be a
    whole number of at least 1; R gives NaN for 0 and uses ``1:nbins`` for
    a fraction. ``generate_all_fixtures.R`` records the R behaviour.

``camera`` / ``camera_pr`` rank test with a set of no genes or of all genes
    With ``use_ranks=True`` such a set has NaN p-values, as in the
    parametric test. R's ``rankSumTestWithCorrelation`` has a zero variance
    there, so both one-sided p-values are 1 and the two-sided p-value is 2,
    which also enters the FDR adjustment of the other sets; pylimma adjusts
    over the sets that have a p-value. With an estimated correlation
    (``inter.gene.cor=NA``) R stops on an empty set. ``generate_all_fixtures.R``
    records the R behaviour.

``camera`` / ``romer`` with missing or infinite values
    Raise "All y values must be finite and non-NA" (the wording of R's
    ``.lmEffects``); R stops in its Fortran QR with "NA/NaN/Inf in foreign
    function call".

``nrot`` / ``nsim`` in ``roast``, ``mroast``, ``romer`` and ``gene_set_test``
    Must be whole numbers of at least 1 (whole-number floats such as
    ``1e4`` are accepted). Below 1, R fails with "invalid 'nrow' value" or,
    for ``geneSetTest``'s ``nsim``, returns ``Inf``; for a fraction such as
    10.5, R recycles random numbers into a 10-row rotation matrix and uses
    10.5 in the p-value denominators, which is not meaningful.

``ndups`` / ``spacing`` in ``unwrap_dups``, ``ave_dups``, ``unique_genelist`` and ``duplicate_correlation``
    Must be whole numbers (whole-number floats such as 2.0 work). R fails
    in ``dim<-`` ("dims do not match the length of object") for a
    fraction; pylimma raises "ndups must be a whole number".

``lm_fit`` with ``ndups > 1`` and ``block``
    Raises "ndups > 1 cannot be combined with block". R's ``gls.series``
    sets ``ndups`` to 1 when ``block`` is given, after ``lmFit`` has reduced
    the probe annotation and ``Amean`` to one row per gene, so R's fit has a
    row per probe while its ``genes`` has a row per gene and ``topTable``
    attaches the annotation to the wrong rows. ``generate_all_fixtures.R``
    records the R behaviour.

``duplicate_correlation`` with a single block
    Raises "block must have at least two levels". R fails in
    ``model.matrix(~factor(block))`` with "contrasts can be applied only to
    factors with 2 or more levels". ``generate_all_fixtures.R`` records the
    R behaviour.

``k`` in ``lm_fit(method="robust")`` / ``mrlm``
    Must be a positive number. ``MASS::rlm`` fails obscurely for ``k = 0``
    ("'size' argument must be a positive integer" in ``chol2inv``) and a
    negative ``k`` ("missing or negative weights not allowed");
    pylimma returned zero coefficients or a LAPACK error.
    ``generate_all_fixtures.R`` records the R behaviour.

``maxit`` in ``lm_fit(method="robust")`` / ``mrlm``
    Must be a whole number of at least 1 (whole-number floats such as 10.0
    work). R's ``MASS::rlm`` loops over ``1L:maxit``, which truncates a
    fraction, and fails with "invalid format '%d'" when a gene does not
    converge within it. ``generate_all_fixtures.R`` records the R
    behaviour.

``top_table`` / ``top_table_f`` with ``number=NaN``
    Raises "number must not be NaN" (R: "missing value where TRUE/FALSE
    needed"). Other values of ``number`` follow R: capped at the number of
    rows, an empty table below 1, and truncation of a non-integer.

``fit_gamma_intercept``
    Missing values in ``y`` or ``offset`` raise "y and offset must not
    contain missing values", and a Newton step that is 0 / 0 (an offset
    of zero where ``y`` is zero) raises "Newton step is undefined"; R
    stops with "missing value where TRUE/FALSE needed" in both cases.
    ``offset`` must be a scalar or have the same length as ``y``; R
    accepts other lengths (recycling a non-constant offset, ignoring the
    length of a constant one).

``top_go`` with an ``ontology`` element that matches nothing
    Raises "'arg' should be one of ...". R's ``match.arg(several.ok =
    TRUE)`` silently drops such an element when another element matches
    (``ontology = c("BP", "XX")`` gives BP only). Abbreviations such as
    ``"B"`` work in both. ``generate_all_fixtures.R`` records the R
    behaviour.

``goana`` / ``kegga`` with set names that differ only in case
    The output columns are the lower-case set names (``up``, ``p_up``), so
    two sets such as ``"A"`` and ``"a"``, or a set named ``"N"`` next to the
    ``n`` column, raise an error naming the clash. R keeps the names as
    given (``A``, ``a``, ``P.A``, ``P.a``). Previously pylimma silently kept
    only one of the sets.

``goana_trend`` with invalid ``index_de`` positions
    Positions must be whole numbers between 0 and ``len(covariate) - 1``
    (or ``index_de`` a boolean mask). R's ``isDE[index.de] <- 1`` treats a
    negative position as "all except", truncates a fraction and silently
    extends ``isDE`` for a position past the end. ``generate_all_fixtures.R``
    records the R behaviour.

``top_go`` / ``top_kegg`` with ``number=NaN``
    Raises "number must not be NaN", as ``top_table`` does (R: "missing
    value where TRUE/FALSE needed"). Other values of ``number`` follow R.

``make_contrasts`` with levels that are not names, or duplicated names
    ``levels`` must give the parameter names: a list of strings, a
    categorical or a design matrix with column names. A matrix without
    column names or numeric values raise an error (R: "argument is of
    length zero"). Duplicated names raise an error; R assigns the
    indicator to the last copy only, so the other copies get zero in every
    contrast. ``generate_all_fixtures.R`` records the R behaviour.

``make_contrasts`` with names other than the levels
    Contrast expressions may use the level names, numbers, ``+ - * / ^``
    and brackets; any other name or a function call raises an error naming
    it. R evaluates the expression in the R session, so ``pi`` and R
    functions such as ``mean(c(A, B))`` work, and a name that is not a
    level resolves to whatever object of that name R finds (``B - D``
    fails with "non-numeric argument to binary operator" because ``D`` is
    ``stats::D``). A contrast given as a number rather than a string
    (``make_contrasts(B=1, ...)``) raises an error; R fills the column with
    the number. The level names ``...`` and ``..1`` raise an error: they
    pass ``make.names()``, but R cannot evaluate them ("'...' used in an
    incorrect context"). An expression over several lines raises an error;
    R parses each line as its own expression and keeps only the last
    (``"A + B\n- C"`` is ``-C``). ``generate_all_fixtures.R`` records the R
    behaviour.

Formula strings containing ``^`` (``model_matrix``, ``lm_fit``, the ``voom`` family)
    Raise an error asking for ``**``. pylimma builds designs from formulas
    with patsy, which evaluates ``I(x^2)`` as Python's bitwise XOR (silently
    wrong numbers for an integer column) and rejects ``(a + b)^2``. In
    patsy, ``I(x**2)`` is R's ``I(x^2)`` and ``(a + b)**2`` is R's
    ``(a + b)^2``. A ``^`` inside a quoted name (``Q("a^b")``) is allowed.

Formula strings with an ordered categorical (``model_matrix``, ``lm_fit``, the ``voom`` family)
    Where patsy would code an ordered categorical with contrasts, pylimma
    raises an error asking for ``C(o, Poly)`` (R's ``contr.poly``, the same
    values) or ``C(o, Treatment)``; this includes ``C(o)`` and ``Q("o")``,
    which name no contrast. R's ``model.matrix`` codes ordered
    factors with ``contr.poly``; patsy ignores the ordering and would
    silently use treatment contrasts. Without contrasts (``~ 0 + o``) both
    give one indicator column per level, and no error is raised.
    ``pd.cut()`` returns an ordered categorical, where R's ``cut()`` returns
    an unordered factor coded with treatment contrasts, so a binned
    covariate raises too; ``.cat.as_unordered()`` gives R's coding of
    ``cut()``. pylimma cannot tell a deliberately ordered factor from a
    binned one, so it asks rather than guess.

``normalize_vsn`` with no non-missing value
    Raises "no row of x has a non-missing value" after vsn's warning that
    the all-missing rows were removed. R's ``normalizeVSN`` fails with
    "Elements of argument 'Sstrat' must be in ascending order".
    ``generate_all_fixtures.R`` records the R behaviour.

``mdplot`` with one column, ``venn_diagram(None)``
    Raise "columns must give two columns of x" and "object must be a
    matrix of test results or venn_counts output, not None". R's
    ``mdplot(x, columns=1)`` takes an NA second column and fails in
    ``plot.window`` ("need finite 'xlim' values"); ``vennDiagram(NULL)``
    fails in ``as.matrix`` ("'data' must be of a vector type").
    ``generate_all_fixtures.R`` records the R behaviour.

``plot_rldf`` asking for more discriminant functions than the design gives
    With two groups the design gives one discriminant function, but
    ``show_dimensions`` always names two. R's ``svd(nu=2)`` then pads the
    metagenes with an orthonormal completion from LAPACK, so R plots and
    returns a second dimension that carries no information and differs
    between LAPACK builds. pylimma raises "the design gives 1 discriminant
    function(s), but show_dimensions / ndim ask for 2".
    ``generate_all_fixtures.R`` records the R behaviour.

``heat_diagram`` with ``names`` of the wrong length
    Raises "names must give one name per row of results". R takes
    ``names[DE]``, so the rows past the end of a short ``names`` are
    labelled NA, and a long one is cut. ``generate_all_fixtures.R`` records
    the R behaviour.

``normalize_cyclic_loess`` with ``iterations`` below 1
    Raises "iterations must be a finite number of 1 or more". R's loop
    ``for (k in 1:iterations)`` runs one pass for values between 0 and 1,
    two for 0 and three for -1, because ``1:0`` counts down.
    ``generate_all_fixtures.R`` records the R behaviour.

Column subsets of a rank-deficient fit
--------------------------------------

For a fit whose design is not of full rank, R's ``[.MArrayLM`` takes
``cov.coefficients`` in pivot order (``jj <- which(pivot %in% j)``), so
``fit[, c("C", "A")]`` has coefficients in the order C, A but a
covariance in the order A, C, and functions that read the subset (such as
``genas``) pair each coefficient with another's variance. pylimma subsets
``cov_coefficients`` in the order of the selected columns, so it lines up
with the coefficients. Selections in pivot order (including every
selection from a full-rank fit) are unaffected.
``generate_all_fixtures.R`` records the R behaviour.

Deliberate interface difference: EList design and weights slots
---------------------------------------------------------------

R's ``voom`` and ``voomWithQualityWeights`` call ``as.matrix()`` on an
``EList`` input, which silently drops every slot except ``E``. pylimma's
``voom`` uses the EList's ``design`` and ``weights`` slots, and
``voom_with_quality_weights`` its ``design`` slot, when the caller does
not pass them explicitly, and emits a ``UserWarning`` each time so that
code ported from R does not change results unnoticed. Passing
``design=`` / ``weights=`` explicitly reproduces R exactly. ``vooma``
matches R.

``vooma_lm_fit`` uses an EList's ``weights`` slot as ``prior_weights``
throughout, again with a ``UserWarning``. R's ``voomaLmFit`` passes the
EList to its first ``lmFit``, which falls back to ``y$weights``; the
intermediate ``lmFit`` (run with a ``block`` and no sample weights) falls
back to it as well, and the final fit does not use it.
Because pylimma treats the slot as prior weights, ``sample_weights=True``
with a weights slot raises an error, as it does with ``prior_weights=``.

``array_weights`` uses an EList's ``design`` slot when ``design=`` is not
given, with a ``UserWarning``. R's ``arrayWeights`` documentation says the
design is "extracted from the data object if available", and its
``getEAWP`` call returns it, but the code never reads it and uses an
intercept-only design. pylimma follows the documentation;
``generate_all_fixtures.R`` records R's literal behaviour.

Deliberate interface difference: messages and names
---------------------------------------------------

``lm_fit`` reports non-estimable coefficients ("Coefficients not
estimable: 3 4") as a ``UserWarning``, so it can be filtered or turned
into an error; R's ``lmFit`` prints the same text with ``cat()``.
``romer`` prints it, as R.

The coefficient columns of an F-test table (``top_table`` with several
coefficients, ``top_table_f``) keep the coefficient or contrast names,
such as ``x2 - x1``; R's ``topTableF`` builds a ``data.frame``, whose
``make.names`` turns them into ``x2...x1``.

``lm_fit(ndups=2)`` (or more) on a matrix with row names names the genes
after the first spot of each group; R's ``unwrapdups`` drops the row
names, so R's fit has no gene names.

With a design without column names, ``lm_fit`` names the coefficients
``x1``..``xp`` for every method. R's ``lmFit`` does so for least squares
and the usual GLS path, but ``mrlm`` (``method="robust"``) and the
gene-by-gene GLS loop (missing values or probe weights) leave them
unnamed, so R's names depend on the path taken.
``generate_all_fixtures.R`` records the R behaviour.

``e_bayes`` and ``treat`` on a fit whose coefficients and
``stdev_unscaled`` are vectors return them, and ``t``, ``p_value`` and
``lods``, as one column, so every slot has one shape for the functions
that read the fit; R keeps the coefficients a vector and its ``eBayes``
returns ``t`` and ``p.value`` as vectors (``lods`` as one column).

``lm_series`` is an internal helper of ``lm_fit`` (not in
``pylimma.__all__``): it needs a ``design`` and has no ``ndups`` or
``spacing``. R exports ``lm.series(M, design=NULL, ndups=1, spacing=1,
weights=NULL)``; use ``lm_fit`` for those arguments.

Deliberate interface difference: plot markers and colours
---------------------------------------------------------

The plot functions take matplotlib markers (``"o"``, ``"^"``, ...) for
``pch``. An integer such as R's ``pch=16`` raises "pch must be a
matplotlib marker ... R's integer pch codes are not translated" (it was
matplotlib's "Unrecognized marker style 16"). Default colours are
pylimma's (red, blue, green, ...), not R's ``palette()``; which points,
lines and legend entries share a colour follows R.

``decide_tests`` returns a plain array, not R's ``TestResults`` class, so a
status taken from it (``plot_md(fit, status=decide_tests(fit))``) is read
like any other status: its values -1, 0 and 1 are the labels, the most
frequent is the background and the rest are highlighted by frequency. R
relabels a ``TestResults`` status as Down / NotSig / Up and highlights Up
and Down in red and blue.
